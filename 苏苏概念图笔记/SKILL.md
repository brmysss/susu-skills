# 苏苏概念图笔记

## 目标

让读者先用一张图把握材料的核心命题、机制、证据与行动路径，再沿节点下钻到原文或概念笔记。默认追求“信息完整但视觉可读”，不是逐段摘要，也不是越多节点越好。

开始前完整阅读 [references/concept-map-standard.md](references/concept-map-standard.md) 与 [references/output-contract.md](references/output-contract.md)。

## 默认交付

必须生成并保留两份互补产物：

1. `01-严格概念图-命题清单.md`：完整语义底稿和审计层。
2. `02-中密度推荐版-Mermaid概念图.md`：默认阅读层，通常 35–45 个唯一概念节点，目标约 40 个。
3. `02-中密度推荐版-Mermaid概念图预览.png`：可选增强。仅当当前环境已有可用渲染器时生成；缺少浏览器、Playwright 或 Mermaid CLI 时直接跳过，不能阻塞前两项交付。

除非用户另有指定，输出到 `{源文件所在目录}/概念图笔记/{源文件名}/`。HTML、Excalidraw、Canvas 和高密度完整版都不是默认产物，仅在用户明确要求时追加。

## 工作流

### 1. 通读并界定

- 完整阅读源材料，不以标题、目录或局部段落代替全文。
- 写出一个焦点问题。图中所有主干节点都应帮助回答它。
- 区分作者主张、证据、案例、个人推论和广告／运营信息；最后一类默认排除。
- 先提取候选概念，不急着画图。概念优先使用名词或简短名词短语。

### 2. 建立完整命题清单

- 每条命题严格写成：`概念 A → 关联词／关系短语 → 概念 B`。
- 单独列出重要节点、次要节点、外部／证据节点。
- 每条命题必须能够自然朗读成一句有意义的话。
- 同一概念使用统一名称；同义词合并，必要时在清单中记录别名。
- 关系词必须表达具体逻辑，如“体现为、阻碍、促成、需要、证明、改善”；不要用空泛的“相关”。
- 先保证语义完整，再考虑视觉压缩。命题清单不能为了让图变小而丢失知识点。

### 3. 压缩为中密度主图

- 从完整清单中选择 35–45 个唯一节点，目标约 40 个，不机械凑数。
- 必须保留：核心问题／结论、3–5 条解释路径、关键机制、重要对照、2–4 个决定性证据、可执行入口与汇合结果。
- 样本规模、人物故事、重复例子、细枝末节留在命题清单、原文或概念笔记中；主图保留它们所证明的机制。
- 如果删去某节点会使一条关键逻辑链断裂，就保留；如果多个节点可被一个已内化概念还原，则允许“升维”为一个节点。
- 不要求单一起点，但应通过布局形成稳定阅读方向：核心入口在上，机制网络居中，结果／行动在下；必要的跨链关系使用虚线。

### 4. 生成 Mermaid

- 使用 `flowchart TB`，默认配置：`curve: basis`、`nodeSpacing: 24`、`rankSpacing: 72`。减少同层横向间距、增加纵向层距，避免图被摊成横向长条。
- 每条边必须带有可朗读的关系标签。不得生成只有箭头没有关系词的边。
- 不用章节名充当概念，不用整句话塞进节点，不用 `subgraph` 框住大段内容来模拟文章目录。
- 采用语义配色：核心红、位置／情境紫、社会机制绿、结构／桥接蓝、行动黄、证据灰色虚线。颜色服务于概念类型，不按原文章节上色。
- 参考 [references/output-contract.md](references/output-contract.md) 的结构和样式，不照抄示例内容。

### 5. 审计与渲染

在交付前逐项检查：

- 焦点问题是否由主图回答。
- 所有边是否都能读成“概念 A + 关系 + 概念 B”。
- 节点是否为概念而非段落摘要；是否有重复概念。
- 主图节点数是否处于 35–45；超出时说明为什么不可压缩，低于时检查是否遗漏关键机制。
- 命题清单中的关键链是否都在图中保留或被明确升维。
- 证据节点是否只保留决定性数字／事实，并清楚指向其支持的概念。
- Mermaid 代码是否闭合、节点 ID 是否唯一、所有引用是否存在；有现成渲染器时，再检查解析结果和严重交叉、遮挡、极端长链或大片空白。
- 有 PNG／SVG 时，宽高比是否通常落在 `1.6–2.0`；超过 `2.2` 视为偏宽，低于 `1.3` 视为偏高。没有渲染器时，仍使用紧凑布局参数并完成 Mermaid 源码交付。

Mermaid Markdown 本身就是正式成品，不依赖 Chromium。优先交付代码块，让 Obsidian、IMA 或其他支持 Mermaid 的阅读器自行显示。

仅当环境已经具备 Node.js、Playwright 和可用浏览器，且用户需要独立 PNG 时，才可执行：

```bash
node scripts/render-mermaid.mjs --input "概念图.md" --output "概念图预览.png"
```

若缺少 Playwright、Chromium、Chrome、Mermaid CLI 或安装权限：

- 不要安装任何依赖或浏览器。
- 不要停止任务，也不要反复提示用户“继续”。
- 跳过 PNG，交付命题清单和 Mermaid Markdown，并注明“预览未在当前环境独立渲染”。

只有用户明确要求导出 PNG 且同意安装依赖时，才可以询问是否安装。若现有渲染器报 Mermaid 语法错误，则修改图结构或转义语法，不要通过删除核心知识掩盖问题。

## 与概念笔记、Wiki 的关系

- 一张概念笔记对应一个可展开的概念；概念图负责表达这些概念之间带方向、带关联词的命题网络。
- 图中节点可链接到已有概念笔记，但先搜索标题和 aliases，避免重复建卡。
- 不自动把 AI 提取结果发布到正式 `Wiki/`。需要加入 Wiki 时遵守知识库的 staging 与人工审核流程。
- 在图后附“概念笔记下钻”和“图外解压缩”说明，指出细节保留在哪里。

## 完成时报告

简要报告焦点问题、命题数量、主图节点数量、保留的证据数量、被移出主图但仍保留在清单中的信息类型、Mermaid 交付状态，以及两份必交成品路径。仅在确实生成 PNG 时报告渲染验证状态。
