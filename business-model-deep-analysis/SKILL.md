# Business Model Deep Analysis

## Purpose

将零散的公开资料重建为一个可验证的商业因果模型，而不是罗列企业事迹、套用商业模式画布或复述宣传稿。

核心任务是回答：

1. 它是如何一步步变成今天的样子？
2. 每个阶段的主要矛盾和破局动作是什么？
3. 用户为什么选择它，为什么付费或传播？
4. 产品、流量、交易、交付和再投入如何相互作用？
5. 哪些是长期能力，哪些只是短期红利或触发器？
6. 这套模式的边界、风险和可复制性如何？

## Select depth

根据用户的问题选择深度：

- **快速拆解**：用户只需要方向性判断，可在已有知识和少量核验上输出。
- **标准研究**：默认模式，搜索多类来源，建立时间线和增长模型。
- **深度报告**：用户要求详尽、全面、尽可能搜索公开资料时，要建立证据台账，执行交叉验证、风险搜索和反事实分析。

如果主体、时间范围和目的已经清楚，直接研究；只有当不同选择会导致实质性不同的报告时才询问用户。

## Workflow

### 1. Define the research question

将用户问题转换为可验证的子问题：

- 研究主体与业务边界；
- 目标时间范围；
- 用户最想理解的结果；
- 需要比较的竞争对手或参照物；
- 最终需要用于企业决策、投资判断、个人IP还是学习迁移。

先列出 3–7 个待验证假设，例如低价、渠道红利、创始人IP、组织能力、产品创新或政策环境。不要把初始假设当作结论。

### 2. Build a research matrix

将搜索拆成多组任务，不要只搜索“为什么成功”：

- 发展史与关键时间；
- 创始人、核心团队与组织；
- 用户与需求；
- 产品、定价与体验；
- 获客、内容、流量与渠道；
- 收入、成本、毛利、复购与单位经济；
- 供应链、交付、人才与激励；
- 竞争对手、替代品与行业结构；
- 投诉、衰退、风险与反面证据。

### 3. Gather and grade evidence

优先使用一手及高可靠来源：政府、监管文件、财报、官方数据、正式访谈和权威媒体。用商业媒体和用户内容补充运营细节、现场体验和反面证据。

为关键证据记录：

```markdown
- 主张：
- 时间：
- 原始来源：
- 来源类型：
- 是否为主体自报：
- 支持哪个结论：
- 局限或冲突：
```

重要结论至少尝试获得两种独立来源。如果只有一个来源，明确降低置信度，不要伪装成已交叉验证。

### 4. Reconstruct the timeline

将关键事件按时间排列，对每个阶段标记：

- 起点状态；
- 当时的主要矛盾；
- 关键动作；
- 结果与数据；
- 新产生的瓶颈；
- 下一阶段的触发条件。

区分“长期积累”、“关键拐点”与“全国级引爆事件”。

### 5. Model the current business

拆解当前的：

- 客户细分与真实任务；
- 价值主张与替代方案；
- 产品矩阵与价格梯度；
- 获客渠道与传播机制；
- 销售、交易和交付；
- 收入来源与成本结构；
- 核心资源、活动与合作伙伴；
- 可观察的单位经济与数据缺口。

### 6. Build the dynamic engine

把下列要素连成可解释的回路：

```text
产品价值
→ 用户体验或成果
→ 口碑、内容或复购
→ 新用户与交易
→ 收入与数据
→ 再投入产品、人才或渠道
→ 产品价值继续提升
```

只有在后一环真正强化前一环时才称为飞轮。否则应该如实写成漏斗、价值链或依赖单一渠道的增长模式。

### 7. Pressure-test the explanation

主动搜索投诉、失败、衰退、竞争对手及关键人物离开等反面证据。追问：

- 如果去掉最显眼的爆款或红利，这套模式还成立吗？
- 价格上涨、平台流量下降或成本上升后会发生什么？
- 核心人物或合作方离开后是否仍可运行？
- 竞争对手复制表面动作后，哪些能力仍无法快速复制？

### 8. Transfer with boundaries

将结论分成：

- 可直接复用的流程；
- 需要结合行业调整的机制；
- 依赖特定资源、时代、平台或个人的不可复制部分；
- 适合用户在 7 天、30 天或 90 天内执行的小规模验证。

不要把大型企业的资源优势直接转换为个人建议。个人迁移应优先找到最小化版本。

### 9. Write from conclusions to evidence

使用结论驱动的结构，而不是按搜索顺序堆积资料：

```text
核心判断
→ 发展时间线
→ 阶段破局
→ 静态商业模式
→ 动态增长机制
→ 壁垒与风险
→ 反事实检验
→ 迁移与行动
→ 证据、限制与来源
```

## Evidence language

在写作中始终区分：

- **事实**：有明确来源支持的事件或数据。
- **推断**：由多个事实归纳得到的解释。
- **假设**：有道理但尚缺乏足够证据的可能性。

对不确定内容使用“可能”“更符合现有证据的解释是”“尚无法从公开资料确认”，不要使用过度确定的口吻。

## Quality gates

在交付前检查：

- 是否包含可追溯的发展时间线？
- 是否解释了每个阶段解决的主要矛盾？
- 是否区分长期基础、拐点和短期引爆事件？
- 是否说清用户价值、产品、流量、交易和交付？
- 是否区分营收、利润、客流、注册用户和曝光？
- 是否标记了主体自报、媒体转引和审计数据？
- 是否真正建立回路，而不是随意把漏斗称为飞轮？
- 是否分析了竞争壁垒、失败风险和反面证据？
- 是否区分可复制机制与不可复制资源？
- 是否说明数据缺口、来源限制和分析置信度？

## Anti-patterns

避免：

- 只使用主体官网和宣传稿；
- 将爆款人物、热搜或平台红利当作唯一原因；
- 把营收、GMV、估值或融资金额写成利润；
- 根据粉丝数直接推断收入；
- 没有反馈回路却强行画飞轮；
- 为了结构完整而编造单位经济数据；
- 只写成功要素，不写风险、代价和不可复制性；
- 将大型组织的资源优势直接变成个人行动建议。
